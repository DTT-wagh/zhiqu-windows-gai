# 热门精选排序适配层

`frontend/dist/zhiqu-recommendations.js` 是无界面的数据适配层。它在原首页 bundle 请求 `/api/learning` 时拦截响应，只重排 `featured` 数组，再交回原首页渲染；不创建新的推荐分区、按钮、标签、理由卡片或 CSS。

## 推荐顺序

候选内容先要求具备 `id`、视频类型、标题、封面、摘要和已发布状态，然后过滤未审核、不安全、广告、危险指令、外链-only、显式失效地址和用户明确不感兴趣的内容。年龄不参与过滤或评分。当前列表接口不携带播放直链时，沿用内容页的 playback 接口做最终可播放性校验。

排序权重集中在 `CHILD_HOT_RECOMMENDATION_WEIGHTS`：

- 近 7 天有效观看：40%；
- 整体完播质量：25%；
- 收藏、分享和高质量互动：20%；
- 内容新鲜度：10%；
- 新内容探索：5%。

排序后会进行系列和学科重排：同一系列最多占热门区域的 40%，并尽量覆盖至少 3 个主题；新内容和低曝光内容获得探索机会。个人学习进度、完成状态、年龄以及“完成第一集后推荐下一集”均不参与热门顺序。排序使用稳定哈希作为同分打散，不使用不可复现的随机数。

## 账号行为

推荐曝光、播放开始、进度节点、完成、跳过、收藏和分享事件按账号保存到 `zq:recommendation-events:{userId}`，同一事件在同一位置只记录一次。这些本地事件只用于产品分析，不参与热门排序，也不展示给其他用户。

## 当前数据不足

正式数据只有一个可用视频时，只返回这一条原始卡片，不创建假视频、不拉伸卡片，也不请求额外推荐地址。过滤后没有可用内容时，原首页继续显示自己的真实空状态。

未来增加视频时，只需在内容数据中提供 `seriesId`、`subject`、`difficulty`、`videoUrl`、`coverUrl`、`summary`、`status`、`publishedAt`、`qualityScore`、近期有效观看数、整体完播率和高质量互动数等字段，不需要修改首页卡片组件。

## 测试

```text
node frontend/tests/zhiqu-recommendations.test.cjs
```

测试覆盖权重、安全过滤、失效地址、单视频、系列去重、学科多样性、探索内容、确定性排序、年龄不参与排序、学习进度不参与排序和账号隔离。
